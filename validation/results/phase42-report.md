四组共同有效且 `usage` 完整的全部 **19/20 题**也可以配对：总 token 依次为 1,925,944、1,792,142、2,402,967、1,651,083，分别相对第一组变化 0%、−6.9%、+24.8%、−14.3%。第 16 题在第三组超时且没有完整 API 用量，因此第三组的**完整 20 题总量未知**；不得将 19 题小计称为完整成本。其他三组完整 20 题的实际总量可在 JSON 中查到，但与第三组比较时必须使用上述共同题号。

压缩在有 RepoMap 时把自动题实际总 token 从 521,062 降到 515,222，约下降 1.1%；在无 RepoMap 时从 880,075 升到 1,149,807，约增加 30.6%。因此本次数据不支持笼统宣称“压缩节省 token”。功能通过数也随配置变化，单次采样不足以证明稳定收益。

## 上下文估算值（与实际用量分开）

trace 中的 `tokens` 是上下文**字符数除以 4**，不是 API 返回的 token。四组观察到的平均上下文峰值估算依次是 4,492.95、6,441.35、3,655.9、5,400.4；它们不能用于计费或与上表相加。第三、四组分别记录 142、130 个压缩 trace 触发事件；其中部分触发没有实际摘要请求。上表的 58、32 才是配对自动题中真正发出的摘要 API 请求数。
